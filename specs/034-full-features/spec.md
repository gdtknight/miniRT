# Feature Specification: Camera Yaw Rotation & Bonus Features

**Feature Branch**: `034-full-features`
**Created**: 2026-02-10
**Status**: Draft
**Input**: User description: "카메라 yaw 회전 추가 (숫자키 1/3), miniRT.md 보너스 요구사항 전체 구현"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Camera Yaw Rotation (Priority: P1)

사용자가 숫자키 1과 3을 눌러 카메라의 좌우 시야를 회전시킬 수 있다.
현재 카메라는 이동(WASDQZ)과 상하 피치(E/C)만 지원하며, 좌우 회전(yaw)이 없어
수평 시점 변경이 불가능하다. 이는 필수 요구사항의 "rotation transformations to cameras"를
충족하지 못하는 문제이다.

**Why this priority**: 필수 요구사항 미충족 항목이므로 최우선 구현 대상

**Independent Test**: 씬 파일을 로드한 후, 숫자키 1/3을 눌러 카메라가 좌/우로 회전하고 시야가 변하는지 확인

**Acceptance Scenarios**:

1. **Given** 씬이 렌더링된 상태, **When** 숫자키 1을 누름, **Then** 카메라가 Y축 기준으로 왼쪽(반시계)으로 5도 회전하고 화면이 갱신됨
2. **Given** 씬이 렌더링된 상태, **When** 숫자키 3을 누름, **Then** 카메라가 Y축 기준으로 오른쪽(시계)으로 5도 회전하고 화면이 갱신됨
3. **Given** 카메라를 여러 번 회전한 상태, **When** S키(리셋)를 누름, **Then** 카메라가 초기 위치와 방향으로 복귀됨
4. **Given** 카메라를 yaw 회전한 상태, **When** pitch(E/C)를 조작, **Then** yaw와 pitch가 독립적으로 동작함

### User Story 2 - Makefile bonus Rule (Priority: P1)

Makefile에 `bonus` rule이 존재하여 보너스 기능 포함 빌드가 가능하다.

**Why this priority**: 필수 요구사항(Makefile rules)에 bonus가 명시되어 있음

**Independent Test**: `make bonus` 실행 시 에러 없이 빌드 완료

**Acceptance Scenarios**:

1. **Given** 클린 상태, **When** `make bonus` 실행, **Then** miniRT가 정상 빌드됨
2. **Given** `make bonus` 완료 상태, **When** 씬 파일로 실행, **Then** 보너스 기능이 동작함

---

### User Story 3 - Checkerboard Pattern (Priority: P2)

오브젝트 표면에 체커보드(바둑판) 패턴을 적용할 수 있다. 씬 파일에서 오브젝트에 패턴 옵션을 지정하면 단색 대신 두 가지 색이 교차하는 패턴으로 렌더링된다.

**Why this priority**: 보너스 요구사항 중 시각적 효과가 크고 구현 복잡도가 낮음

**Independent Test**: 씬 파일에 체커보드 옵션이 있는 평면을 렌더링하여 패턴 확인

**Acceptance Scenarios**:

1. **Given** 체커보드 옵션이 적용된 평면, **When** 렌더링, **Then** 두 색이 교차하는 바둑판 패턴이 표면에 보임
2. **Given** 체커보드 옵션이 적용된 구, **When** 렌더링, **Then** 구 표면에 체커보드 패턴이 UV 매핑되어 보임
3. **Given** 체커보드 옵션이 적용된 원기둥, **When** 렌더링, **Then** 원기둥 측면과 캡에 체커보드 패턴이 보임
4. **Given** 체커보드 옵션이 없는 오브젝트, **When** 렌더링, **Then** 기존과 동일하게 단색으로 렌더링됨

---

### User Story 4 - Colored & Multi-spot Lights (Priority: P2)

씬에 여러 개의 점 광원(spot light)을 배치할 수 있으며, 각 광원에 고유한 색상을 지정할 수 있다.

**Why this priority**: 보너스 요구사항. 조명 색상은 이미 파싱/적용되고 있으므로 다중 광원 지원이 핵심

**Independent Test**: 서로 다른 색의 광원 2개 이상이 있는 씬 파일을 렌더링하여 혼합 조명 확인

**Acceptance Scenarios**:

1. **Given** 빨간 광원과 파란 광원이 있는 씬, **When** 렌더링, **Then** 양쪽 광원의 색이 오브젝트에 혼합되어 보임
2. **Given** 광원 3개가 서로 다른 위치에 있는 씬, **When** 렌더링, **Then** 각 광원별로 독립적인 그림자가 생성됨
3. **Given** 다중 광원 씬, **When** 광원 하나를 이동(키 조작), **Then** 해당 광원의 조명과 그림자만 변경됨
4. **Given** L 항목이 여러 개인 씬 파일, **When** 파싱, **Then** 중복 에러 없이 모든 광원이 로드됨

---

### User Story 5 - Cone Object (Priority: P2)

원뿔(cone) 오브젝트를 씬에 배치하고 렌더링할 수 있다.

**Why this priority**: 보너스 요구사항의 2차 곡면 오브젝트

**Independent Test**: 원뿔이 포함된 씬 파일을 렌더링하여 올바른 형태 확인

**Acceptance Scenarios**:

1. **Given** 원뿔이 있는 씬 파일, **When** 렌더링, **Then** 원뿔 형태가 올바르게 보임 (꼭짓점에서 밑면까지 테이퍼)
2. **Given** 원뿔 오브젝트, **When** 이동/회전 키 조작, **Then** 다른 오브젝트와 동일하게 변환됨
3. **Given** 원뿔 오브젝트, **When** 리사이즈 키 조작, **Then** 반지름과 높이가 변경됨
4. **Given** 광원과 원뿔, **When** 렌더링, **Then** 원뿔에 올바른 그림자와 조명이 적용됨
5. **Given** 카메라가 원뿔 내부에 위치, **When** 렌더링, **Then** 내부에서 본 면이 올바르게 렌더링됨

---

### User Story 6 - Bump Map Textures (Priority: P3)

오브젝트 표면에 범프맵을 적용하여 울퉁불퉁한 표면 효과를 만들 수 있다. 씬 파일에서 범프맵 파일 경로를 지정하면 법선이 교란되어 입체적 질감이 렌더링된다.

**Why this priority**: 보너스 요구사항 중 구현 복잡도가 가장 높음 (UV 매핑 + 텍스처 로딩 + 법선 교란)

**Independent Test**: 범프맵이 적용된 구를 렌더링하여 표면에 요철 효과가 보이는지 확인

**Acceptance Scenarios**:

1. **Given** 범프맵 XPM 파일이 지정된 구, **When** 렌더링, **Then** 구 표면에 텍스처 기반 요철 효과가 보임
2. **Given** 범프맵이 적용된 평면, **When** 렌더링, **Then** 평면 표면에 범프 효과가 보임
3. **Given** 범프맵 파일이 존재하지 않는 경우, **When** 파싱, **Then** "Error\n" + 명시적 에러 메시지 출력
4. **Given** 범프맵이 없는 오브젝트, **When** 렌더링, **Then** 기존과 동일하게 매끄러운 표면으로 렌더링됨

---

### Edge Cases

- 카메라 yaw를 360도 이상 회전해도 방향 벡터가 정규화 상태를 유지하는가?
- ~~카메라를 수직(위/아래) 방향으로 향한 상태에서 yaw 회전 시 gimbal lock이 발생하지 않는가?~~ → 별도 처리 불필요. 방향이 Y축과 평행하면 yaw 효과 없음 (수학적으로 정확한 동작). 실사용에서 도달 확률 극히 낮음
- 다중 광원에서 모든 광원이 한 점에 집중될 때 색 값이 255를 초과하지 않고 클램핑되는가?
- 체커보드 패턴의 스케일이 매우 작거나 클 때 렌더링이 정상 동작하는가?
- 원뿔의 높이가 0에 가까울 때 (디스크에 수렴) 렌더링이 올바른가?
- 원뿔의 반각이 극단적 값(거의 0도 또는 거의 90도)일 때 교차 계산이 안정적인가?
- 범프맵 XPM 파일의 크기가 매우 크거나 형식이 잘못된 경우 적절한 에러 처리가 되는가?
- ~~씬 파일에 L 항목이 0개인 경우~~ → L 최소 1개 필수, 0개이면 파싱 에러

## Requirements *(mandatory)*

### Functional Requirements

**카메라 Yaw 회전**
- **FR-001**: 프로그램은 숫자키 1을 누르면 카메라를 Y축 기준으로 왼쪽(반시계)으로 5도 회전시켜야 한다
- **FR-002**: 프로그램은 숫자키 3을 누르면 카메라를 Y축 기준으로 오른쪽(시계)으로 5도 회전시켜야 한다
- **FR-003**: Yaw 회전 후 카메라 방향 벡터는 항상 정규화 상태를 유지해야 한다
- **FR-004**: S키 리셋 시 yaw 회전도 초기 상태로 복귀해야 한다

**Makefile**
- **FR-005**: Makefile에 `bonus` rule이 존재해야 한다. `bonus`는 `all`과 동일한 바이너리를 생성한다. 근거: subject의 `_bonus.{c/h}` 분리 규칙은 보너스 미구현 시에만 해당하며, 전체 구현 시 별도 분기가 불필요하다

**체커보드 패턴**
- **FR-006**: 씬 파일에서 오브젝트 라인 끝에 `checker:R,G,B` 선택적 파라미터로 체커보드 패턴을 지정할 수 있어야 한다
- **FR-007**: 체커보드 패턴은 구, 평면, 원기둥, 원뿔에 적용 가능해야 한다
- **FR-008**: 체커보드의 보조 색상은 `checker:R,G,B` 형식으로 지정하며, 미지정 시 단색으로 렌더링한다
- **FR-009**: 패턴 미지정 시 기존 단색 렌더링과 동일하게 동작해야 한다
- **FR-009a**: `checker:`와 `bump:` 옵션은 순서에 관계없이 파싱되어야 한다
- **FR-009b**: 인식하지 못하는 보너스 토큰(예: `foo:bar`)이 있으면 파싱 에러를 반환해야 한다

**다중 광원**
- **FR-010**: 씬 파일에 L 항목을 1개 이상 여러 개 선언할 수 있어야 한다 (0개이면 파싱 에러)
- **FR-010a**: 광원 최대 개수(16개)를 초과하면 파싱 에러를 반환해야 한다
- **FR-011**: 각 광원은 독립적인 위치, 밝기, 색상을 가져야 한다
- **FR-012**: 조명 계산 시 모든 광원의 기여를 합산하여 적용해야 한다
- **FR-013**: 각 광원별로 독립적인 그림자를 생성해야 한다
- **FR-014**: 최종 색상 값은 RGB 각 채널 [0, 255] 범위로 클램핑되어야 한다
- **FR-015**: `=` 키를 누르면 조작 대상 광원이 다음 광원으로 순환 선택되어야 한다 (첫 번째 광원이 기본 선택, 마지막 광원 다음은 첫 번째로 순환)

**원뿔**
- **FR-016**: 씬 파일에서 `co` 식별자로 원뿔 오브젝트를 선언할 수 있어야 한다
- **FR-017**: 원뿔은 중심 좌표, 축 방향, 밑면 지름, 높이, 색상을 파라미터로 가져야 한다. 높이의 중앙을 기준 좌표로 사용한다 (원기둥과 동일한 좌표 규칙)
- **FR-018**: 원뿔의 측면과 밑면(cap)에 대한 레이 교차가 올바르게 계산되어야 한다
- **FR-019**: 원뿔은 이동, 회전, 리사이즈가 가능해야 한다
- **FR-020**: 원뿔 내부에서의 레이 교차가 올바르게 처리되어야 한다

**범프 매핑**
- **FR-021**: 씬 파일에서 오브젝트 라인 끝에 `bump:파일경로.xpm` 선택적 파라미터로 범프맵을 지정할 수 있어야 한다
- **FR-022**: 범프맵은 구, 평면, 원기둥, 원뿔에 적용 가능해야 한다
- **FR-023**: 범프맵 적용 시 교차점의 법선이 텍스처 값에 따라 교란되어야 한다
- **FR-024**: 범프맵 파일이 유효하지 않은 경우 "Error\n" + 명시적 에러 메시지를 출력해야 한다
- **FR-025**: 범프맵 미지정 시 기존 매끄러운 표면과 동일하게 동작해야 한다

### Key Entities

- **Camera**: 위치, 방향(yaw/pitch 반영), FOV, 초기 상태
- **Light**: 위치, 밝기, 색상 (다중 인스턴스 지원)
- **Cone**: 중심 좌표(높이 중앙), 축 방향, 밑면 지름, 높이, 색상
- **Checkerboard Pattern**: 적용 여부, 보조 색상, 스케일
- **Bump Map**: XPM 파일 경로, 텍스처 데이터, UV 매핑 정보

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 카메라 yaw 회전(키 1/3) 사용 시 화면이 즉시 갱신됨
- **SC-002**: 체커보드 패턴이 적용된 평면이 규칙적인 바둑판 무늬로 렌더링됨
- **SC-003**: 서로 다른 색의 광원 2개 이상이 있는 씬에서 혼합 조명이 올바르게 표현됨
- **SC-004**: 원뿔 오브젝트가 올바른 기하학적 형태로 렌더링되며 그림자가 정확함
- **SC-005**: 범프맵이 적용된 오브젝트 표면에 울퉁불퉁한 질감 효과가 시각적으로 확인됨
- **SC-006**: `make bonus` 명령이 에러 없이 빌드 완료됨
- **SC-007**: 모든 보너스 기능이 42 Norm v4.1을 통과함 (norminette 에러 0건)
- **SC-008**: 잘못된 씬 파일(잘못된 원뿔 파라미터, 없는 범프맵 등)에 대해 "Error\n" + 명시적 메시지가 출력됨

## Clarifications

### Session 2026-02-10

- Q: 보너스 옵션(체커보드/범프맵)의 씬 파일 문법 형식은? → A: 기존 오브젝트 라인 끝에 선택적 파라미터 추가 (예: `sp 0,0,20 12.6 255,0,0 checker:0,255,0 bump:texture.xpm`). 추가 토큰이 없으면 기본값 적용하여 기존 씬 파일과 하위호환 유지.
- Q: 원뿔의 기준 좌표는 꼭짓점(apex)인가 중심(center)인가? → A: 중심(center) 기준. 원기둥과 동일하게 높이의 중앙 좌표를 지정하며, 꼭짓점과 밑면이 ±half_height에 위치.
- Q: 다중 광원 시 조작 대상 전환 방식은? → A: 첫 번째 광원이 기본 선택. `=` 키(shift 없이)를 누르면 다음 광원으로 순환 선택.
- Q: 체커보드 패턴이 원뿔에도 적용되어야 하는가? → A: 원뿔 포함. FR-007을 "구, 평면, 원기둥, 원뿔"로 확장 (FR-022 범프맵과 동일 범위).
- Q: 씬 파일에 L(광원) 항목이 0개인 경우 처리 방식은? → A: L 최소 1개 필수. 0개이면 파싱 에러 (기존 동작 유지).
- Q: 보너스 옵션 파싱 순서 및 미인식 토큰 처리는? → A: `checker:`/`bump:` 순서 자유, 미인식 토큰은 파싱 에러.
- Q: 카메라 수직 방향에서 yaw gimbal lock 처리? → A: 별도 처리 불필요. 실사용 도달 확률 극히 낮고, 발생 시 수학적으로 정확한 동작 (효과 없음).

## Assumptions & Constraints

### Assumptions

- 카메라 yaw 회전 각도는 기존 pitch(5도)와 동일하게 5도 단위로 적용
- 체커보드 패턴 스케일은 고정값 사용 (씬 파일에서 별도 지정 불필요)
- 범프맵 파일 형식은 MiniLibX가 지원하는 XPM 형식 사용
- 원뿔 씬 파일 형식: `co [center] [axis] [diameter] [height] [R,G,B]` (원기둥과 동일하게 중심 기준)
- 다중 광원 시 `=` 키로 조작 대상 광원 순환 전환 (첫 번째 광원 기본 선택)
- 기존 단일 광원 씬 파일은 그대로 호환됨
- Specular reflection(Phong model)은 이미 구현되어 있으므로 본 스펙에서 제외
- 디바운스 렌더링 파이프라인(50ms LQ preview, 150ms full render)은 033에서 구현 완료된 기존 기능이며, 본 스펙의 신규 키 입력도 동일 파이프라인을 통해 렌더링됨

### Dependencies (기존 기능 의존)

- **033-hud-input-optimization**: 디바운스 FSM, LQ preview 파이프라인
- **기존 파서**: 현재 파서는 오브젝트 라인의 표준 파라미터 이후 추가 토큰을 에러 처리함. 보너스 옵션 파싱(FR-009a/b)을 위해 이 동작을 변경해야 하며, `checker:`/`bump:` prefix가 있는 토큰만 허용하고 그 외는 기존과 동일하게 에러 처리한다

### Constraints

- 42 Norm v4.1 준수 (25줄/함수, 5변수/함수, 5함수/파일, 4파라미터/함수)
- MiniLibX 라이브러리만 사용 가능 (외부 이미지 로딩 라이브러리 불가)
- 허용 함수: open, close, read, write, printf, malloc, free, perror, strerror, exit, math.h, MiniLibX, gettimeofday
- 보너스 파일은 subject에 별도 지정이 없으므로 기존 소스에 통합 가능
