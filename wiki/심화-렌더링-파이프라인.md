# 심화: 렌더링 파이프라인

> 이 문서는 누구를 위한 것인가
> - `mlx_loop` 이 한 번 돌 때 무슨 일이 일어나는지 초 단위로 따라가고 싶은 사람
> - 디바운스 FSM의 네 상태가 언제 전이하는지 확실히 하고 싶은 사람

## 1. 진입점 — `mlx_loop`

`main()` 이 `mlx_loop()` 을 호출하면 MLX가 내부적으로 이벤트를 폴링하면서 루프 훅 `render_loop()` 을 반복 호출합니다. 이 루프 훅이 "프레임 하나를 판단·렌더" 하는 중심입니다.

```
mlx_loop (외부)
  ⇢ 매 tick ⇢ render_loop(render)   [src/render/render_loop.c:71]
```

## 2. render_loop — 프레임 판단자

`src/render/render_loop.c:71`:

```c
int render_loop(void *param)
{
    t_render *render = (t_render *)param;
    int rendered = 0;
    debounce_update(&render->debounce, render);   // (A) FSM tick
    rebuild_bvh_if_dirty(render);                  // (B) 필요시 BVH 재빌드
    if (render_has_flag(render, RENDER_DIRTY))
        rendered = execute_render_pass(render);    // (C) 실제 렌더
    if (render->hud.visible && (render->hud.dirty || rendered))
    {
        render->keyguide.dirty = 1;
        if (!rendered)
            mlx_put_image_to_window(...);          // 이미지 다시 올림
        hud_render(render);                        // (D) HUD 덮어그리기
        keyguide_render(render);
    }
    return (0);
}
```

### (A) debounce_update

키 입력이 없으면 대부분 빠르게 반환. 자세한 전이는 아래 섹션 5.

### (B) BVH 재빌드

사용자가 객체를 움직여 `RENDER_BVH_DIRTY` 플래그를 세웠다면, `build_scene_bvh()` 로 트리를 다시 만듭니다(`render_loop.c:27`).

### (C) execute_render_pass

`render_loop.c:46`:

```c
render_set_flag(render, RENDER_RENDERING);
metrics_start_frame(...);
render_scene_to_buffer(render->scene, render);  // ← 픽셀 루프
render_clear_flag(render, RENDER_RENDERING);
metrics_end_frame(...);
mlx_put_image_to_window(mlx, win, img, 0, 0);   // 버퍼 → 창
render_clear_flag(render, RENDER_DIRTY);
```

## 3. render_scene_to_buffer — 픽셀 루프

`src/render/render.c:132`:

```c
if (render_has_flag(render, RENDER_LOW_QUALITY))
    return (render_low_quality(scene, render));   // 2x2 블록 미리보기
y = 0;
while (y < WINDOW_HEIGHT) {
    x = 0;
    while (x < WINDOW_WIDTH) {
        render_pixel(scene, render, x, y);
        x++;
    }
    y++;
}
```

`render_pixel()` 하나의 처리:

```
(x, y) → NDC (u, v) → create_camera_ray → trace_ray → put_pixel_to_buffer
```

- **NDC 변환**: `u = 2x/W - 1`, `v = 1 - 2y/H` (`render.c:56`).
- **광선 생성**: `create_camera_ray()`. basis 캐시 + FOV 스케일로 방향 계산 (`render_camera.c:52`).
- **트레이싱**: `trace_ray()`. BVH → 평면 보조 리스트 → 셰이딩 (`render_trace.c:102`).
- **픽셀 기록**: `mlx_img_put_pixel()` 이 공유 메모리 버퍼에 직접 기입 (`render.c:33`).

### 저품질 미리보기

`render_low_quality()` 는 2픽셀 간격으로만 광선을 쏘고, `draw_pixel_block()` 이 2×2 같은 색을 찍어 4배 빠르게 프레임을 냅니다 (`render.c:74`). 사용자가 드래그하는 동안에만 사용.

## 4. trace_ray — BVH + 평면 분리 + 셰이딩

`src/render/render_trace.c:102`:

```c
metrics_add_ray(...);
hit.distance = INFINITY;
if (scene->bvh && scene->bvh->enabled && scene->bvh->root) {
    if (bvh_intersect(scene->bvh, *ray, &hit, scene))    found = 1;
    if (intersect_planes(scene, ray, &hit))              found = 1;
    if (found) return (apply_lighting(scene, &hit));
    return ((t_color){0, 0, 0});
}
if (check_all_objects(scene, ray, &hit))
    return (apply_lighting(scene, &hit));
return ((t_color){0, 0, 0});
```

- BVH가 있으면 BVH + 평면 리스트를 둘 다 테스트하여 `hit.distance` 가 최소인 것을 남김.
- 둘 다 없으면 모든 물체를 순회 (fallback).
- 어떤 것에도 맞지 않으면 검정.

## 5. 디바운스 FSM — 네 가지 상태

사용자가 키를 눌러 카메라를 움직이는 동안은 "저품질 미리보기"를 돌리고, 손을 뗀 뒤 최종 품질로 다시 그립니다. 이 흐름을 상태 머신으로 관리합니다. (`includes/render/render_debounce.h:27`)

```
  키 입력                           
   │                                
   ▼                                
┌─────┐   input    ┌────────┐   timer  ┌────────┐
│IDLE │ ─────────► │ ACTIVE │ ───────► │ FINAL  │
└─────┘            └────────┘          └────────┘
   ▲                  ▲  │                 │
   │                  │  │  입력 있으면      │ dirty 끝나면
   │                  └──┘   유지/연장      ▼
   │     timer        ┌────────┐
   └───────────────── │COOLDOWN│
                      └────────┘
```

- **IDLE**: 아무 일 없음.
- **ACTIVE**: 키가 눌린 직후. 타이머 갱신. 일정 간격마다 `RENDER_LOW_QUALITY | RENDER_DIRTY` 를 세워 미리보기 프레임을 찍음 (`render_debounce.c:60`).
- **FINAL**: 타이머 만료(150ms). `RENDER_LOW_QUALITY` 해제, `RENDER_DIRTY` 세움 → 다음 tick에서 풀 퀄리티 렌더 (`render_debounce.c:73`).
- **COOLDOWN**: 풀 퀄리티 렌더가 끝나면 진입. 350ms 이후 IDLE 로 복귀 (`render_debounce.c:108`).

상수는 `render_debounce.h:19`에서 정의:

```c
# define DEBOUNCE_DEFAULT_DELAY_MS       150
# define DEBOUNCE_COOLDOWN_MS            350
# define DEBOUNCE_PREVIEW_MIN_INTERVAL_MS 50
```

### 키 입력 처리

키 핸들러(예: `handle_camera_keys()` in `src/interact/input/input_dispatch.c:27`)는 상태를 바꾼 뒤 `debounce_on_input()` 을 호출해 FSM을 틱시킵니다.

## 6. HUD 오버레이

HUD는 이미지 버퍼가 아니라 `mlx_string_put` 으로 창에 직접 문자열을 찍습니다. 프레임을 다시 올린 뒤 덮어쓰기 때문에, 렌더가 있었거나 HUD가 dirty 일 때만 `hud_render()` 와 `keyguide_render()` 가 호출됩니다 (`render_loop.c:82`).

## 7. 타임라인 예시

```
t=0ms    키 W 누름
         → debounce_on_input → ACTIVE, low_quality 플래그
t=50ms   (next tick) render_loop → low-quality 렌더
t=60ms   키 W 계속 → ACTIVE timer 갱신
...
t=120ms  키 놓음 (마지막 입력)
t=270ms  ACTIVE → FINAL, dirty 세팅 → 풀 퀄리티 렌더
t=280ms  렌더 완료 → COOLDOWN
t=630ms  COOLDOWN → IDLE
```
