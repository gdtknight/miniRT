# 개념: 좌표계와 카메라

> 이 문서는 누구를 위한 것인가
> - "픽셀 (x, y)" 가 어떻게 "3D 광선"이 되는지 궁금한 사람
> - FOV, aspect ratio, 카메라 basis라는 용어를 코드에서 확인하고 싶은 사람

## 1. 세 가지 좌표계

miniRT에서 한 픽셀이 광선으로 변하는 동안 세 가지 좌표계를 거칩니다.

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│ 스크린 좌표      │ ──► │ 정규화 좌표 NDC  │ ──► │ 월드 공간 광선  │
│ (x, y) 픽셀      │     │ (u, v) ∈ [-1, 1]│     │ (origin, dir)   │
│ 0..W, 0..H       │     │                  │     │                 │
└─────────────────┘     └─────────────────┘     └─────────────────┘
```

각 단계는 `src/render/render.c:49`의 `render_pixel()` 과 `src/render/render_camera.c:52`의 `create_camera_ray()` 에 구현되어 있습니다.

## 2. 스크린 → NDC 변환

픽셀 좌표 (0..W-1, 0..H-1) 를 [-1, 1] 범위의 정규화된 좌표로 바꿉니다.

```c
// src/render/render.c:56
u = (2.0 * x / (double)WINDOW_WIDTH) - 1.0;
v = 1.0 - (2.0 * y / (double)WINDOW_HEIGHT);
```

- `u`: 왼쪽 가장자리 -1, 오른쪽 +1
- `v`: y는 위아래가 뒤집혀야 하므로 `1 - ...` 로 부호 반전 (스크린 y는 아래로 증가, 월드 y는 위로 증가)

## 3. FOV와 시야각

FOV(Field of View)는 "카메라가 한 번에 볼 수 있는 각도"입니다. miniRT는 세로 FOV를 도(degree)로 입력받고 파서에서 [1, 179] 범위로 강제합니다 (`src/scene/parser/parse_elements.c:127`).

NDC의 [-1, 1] 범위를 실제 시야각에 맞추려면 `tan(fov/2)` 스케일을 곱해야 합니다.

```c
// src/render/render_camera.c:31
camera->cache.fov_scale = tan(camera->fov * 0.5 * M_PI / 180.0);
```

FOV가 크면 `tan` 값이 커져 렌즈가 더 넓어지고(광각), 작으면 망원이 됩니다.

### 종횡비(aspect ratio)

창의 가로세로 비율 보정을 위해 x 방향에만 `aspect_ratio`를 곱합니다.

```c
// src/render/render_camera.c:61
pixel_pos = vec3_add(pixel_pos, vec3_multiply(c->right,
            x * c->fov_scale * c->aspect_ratio));
pixel_pos = vec3_add(pixel_pos, vec3_multiply(c->up, y * c->fov_scale));
```

이 두 줄이 "정규화 좌표를 3D 공간의 픽셀 위치로 펼치는" 핵심입니다.

## 4. 카메라 basis (u, v, w 또는 right, up, forward)

카메라를 기준으로 3D 공간을 설명하려면 서로 직교하는 세 방향축이 필요합니다. miniRT는 **right / up / forward(direction)** 이라는 이름을 씁니다.

```
                    up (↑)
                    │
                    │
                    └─── right (→)
                   /
                  /
         forward (앞, direction)
```

### `right` 구하기

카메라의 yaw(좌우 회전각)만으로 수평 회전을 표현하므로:

```c
// src/render/render_camera.c:32
camera->cache.right.x = -cos(camera->yaw);
camera->cache.right.y = 0;
camera->cache.right.z = sin(camera->yaw);
```

right는 항상 y=0 인 수평면에 있습니다(카메라 롤 없음).

### `up` 구하기

right와 forward가 모두 정해지면 둘에 수직인 벡터가 up입니다. 외적으로 한 번에 계산:

```c
// src/render/render_camera.c:35
camera->cache.up = vec3_normalize(vec3_cross(camera->cache.right,
            camera->direction));
```

### 캐시

이 basis 계산은 픽셀마다 똑같으므로 `t_camera_cache` 에 저장해 두고, 카메라가 움직일 때만 `valid = 0` 으로 무효화합니다 (`includes/scene/scene.h:43`).

## 5. 픽셀 → 광선 공식 유도

최종적으로 광선 방향은 다음 세 벡터의 합입니다.

$$\vec{d} = \vec{forward} + u \cdot s \cdot a \cdot \vec{right} + v \cdot s \cdot \vec{up}$$

여기서 $s = \tan(\text{FOV}/2)$, $a$ 는 aspect ratio. 정규화 후 광선 방향이 됩니다.

```c
// src/render/render_camera.c:60-65
pixel_pos = camera->direction;                                          // forward
pixel_pos = vec3_add(pixel_pos, vec3_multiply(c->right,
            x * c->fov_scale * c->aspect_ratio));                       // + u * s * a * right
pixel_pos = vec3_add(pixel_pos, vec3_multiply(c->up, y * c->fov_scale));// + v * s * up
ray.origin = camera->position;
ray.direction = vec3_normalize(pixel_pos);
```

### `inv_dir`

광선 구조체는 방향의 역수도 함께 저장합니다 (`src/render/render_camera.c:66`). AABB slab 테스트에서 나눗셈을 곱셈으로 바꾸기 위함입니다. 자세한 이유는 [개념: AABB와 공간분할](개념-AABB와-공간분할) 참고.

## 6. 피치(pitch)와 요(yaw)

카메라 회전 상태는 두 각도로 관리됩니다.

- `yaw`: y축 기준 좌우 회전
- `pitch`: 수평축 기준 위아래 회전

파서는 씬에 적힌 방향 벡터로부터 이 두 각도를 역산합니다 (`src/scene/parser/parse_elements.c:95`):

```c
scene->camera.pitch = asin(scene->camera.direction.y);
scene->camera.yaw   = atan2(scene->camera.direction.x,
                            scene->camera.direction.z);
```

사용자가 E/C 키로 피치를 바꾸면 `direction` 을 다시 계산하고 basis 캐시를 무효화합니다.
