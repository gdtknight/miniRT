# 심화: 메트릭스와 디버그

> 이 문서는 누구를 위한 것인가
> - FPS / 광선 수 / BVH 노드 방문수 같은 지표가 어디에서 집계되는지 알고 싶은 사람
> - `--bvh-vis` 콘솔 덤프의 생성 경로를 추적하고 싶은 사람

## 1. 메트릭스 구조

`includes/metrics.h:48`:

```c
typedef struct s_metrics
{
    t_frame_timing  timing;   // FPS, render_time_us, history
    t_ray_metrics   ray;      // rays_traced, intersect_tests, shadow_intersect_tests
    t_bvh_metrics   bvh;      // nodes_visited, tests_skipped
}   t_metrics;
```

`t_scene.metrics` 에 임베드되어 있어 씬 전체에서 공유됩니다.

## 2. 프레임 타이밍 — 히스토리 링 버퍼

`t_frame_timing` 은 `frame_times_us[FRAME_HISTORY_SIZE(=60)]` 링 버퍼를 유지합니다 (`metrics.h:36`).

### start_frame

`src/metrics/metrics_frame.c:65`:

```c
ray.rays_traced          = 0;
ray.intersect_tests      = 0;
ray.shadow_intersect_tests = 0;
bvh.nodes_visited        = 0;
bvh.tests_skipped        = 0;
gettimeofday(&timing.start_time, NULL);
```

프레임마다 카운터 리셋하고 시간 기록 시작.

### end_frame

`metrics_frame.c:114`:

```c
t->render_time_us             = timer_elapsed_us(&t->start_time);
t->frame_times_us[frame_index] = render_time_us;
t->frame_index                 = (frame_index + 1) % FRAME_HISTORY_SIZE;
t->frame_count++;
t->fps                         = calculate_fps_internal(t);
```

FPS 는 최근 60 프레임의 평균 시간으로부터 `1e6 / avg_us` 로 산출 (`calculate_fps_internal`, `metrics_frame.c:83`). 0인 슬롯은 집계에서 제외하여 시작 초기 잡음을 방지.

## 3. 카운터 — 핫패스에서 증분

`src/metrics/metrics_counters.c` 에 `metrics_add_ray`, `metrics_add_intersect_test`, `metrics_add_shadow_intersect`, `metrics_add_bvh_node_visit`, `metrics_add_bvh_skip` 가 정의되어 있고, 각 렌더/트레이스 함수 핫패스에서 직접 호출됩니다.

- `trace_ray()` 시작: `metrics_add_ray()` (`render_trace.c:107`)
- 리프 교차 테스트 직전: `metrics_add_intersect_test()`
- 그림자 교차 테스트 직전: `metrics_add_shadow_intersect()`
- BVH 노드 방문 시: `metrics_add_bvh_node_visit()` / AABB 미스 시 `metrics_add_bvh_skip()` (`bvh_traverse.c`, `bvh_any_hit.c`)

## 4. 요약 출력

`metrics_print_summary()` 는 한 프레임 종료 시 stdout 에 지표를 찍습니다. 호출 조건은 플래그:

```c
// src/render/render_loop.c:53
if (render_has_flag(render, RENDER_ENABLE_METRICS_PRINT))
    metrics_print_summary(&render->scene->metrics, render->scene->objects.count);
```

기본값에서 이 플래그는 꺼져 있습니다. 개발 시 소스에서 활성화해 콘솔 벤치마크를 할 수 있습니다.

## 5. HUD 퍼포먼스 섹션

`hud_render_performance()` (`src/interact/hud/hud_performance.c`) 가 metrics 를 읽어 화면에 FPS/렌더 시간/광선 수/테스트 수를 표시합니다. HUD 활성화(H 키) 시 실시간 피드백 제공.

## 6. --bvh-vis 콘솔 덤프

실행 시 `--bvh-vis` 플래그가 붙으면 `main.c:44` 에서 `bvh_vis = 1`. BVH 빌드 직후 `bvhd_run()` 이 한 번 호출됩니다:

```c
// src/main.c:144
if (bvh_vis && scene->bvh)
    scene->bvh->visualize = 1;
bvhd_run(scene->bvh, scene);
```

또한 BVH 리빌드 시에도 `render_loop.c:33` 에서 다시 한번 호출되어 구조 변화를 추적.

### 덤프 구현

`src/spatial/debug/bvhd_init.c:21` 의 `bvhd_run()`:

```c
if (!bvh || !bvh->root || !bvh->visualize) return;
prefix = bvhd_prefix_init();
ctx.prefix = &prefix;
ctx.scene  = scene;
bvhd_print_tree(bvh->root, &ctx, &stats);
bvhd_prefix_destroy(&prefix);
```

`bvhd_print_tree()` (`bvhd_tree.c`) 가 트리를 재귀적으로 타고 내려가며:

- 현재 노드 정보 포맷: `bvhd_format.c` 의 `bvhd_format_node()`
- 트리 접두사 그리기: `bvhd_prefix.c` / `bvhd_prefix_push.c`
- 노드 라인 출력: `bvhd_print.c:24` 의 `bvhd_print_node()`

출력 예시:

```
└── internal [depth=0] [min=(-5,-5,-5) max=(5,5,5)]
    ├── internal [depth=1] [...]
    │   ├── leaf [depth=2] [...] (sp-1, sp-2)
    │   └── leaf [depth=2] [...] (cy-1)
    └── ...
```

`└──` / `├──` 유니코드는 `bvhd_print.c:28`에 하드코딩.

### 통계

`t_bvh_stats` 에 노드 수/리프 수/평균 depth 등을 집계해 마지막에 요약을 출력합니다 (`bvhd_stats.c`).

## 7. 프로파일링 팁

- 객체 수가 늘 때 `intersect_tests` 가 선형으로 폭발하면 BVH가 효과적이지 않은 것 — AABB가 너무 겹치는지 확인.
- `shadow_intersect_tests` 가 `intersect_tests` 보다 수배 많은 게 정상 (샘플당 16개 × 광원 수).
- FPS가 저품질 프레임에서도 낮으면 셰이딩(fast_pow32, shadow sample 수)이 병목.
