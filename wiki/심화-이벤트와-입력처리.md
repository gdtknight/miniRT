# 심화: 이벤트와 입력 처리

> 이 문서는 누구를 위한 것인가
> - MLX 이벤트가 어디에서 가로채어지고 키 핸들러로 전달되는지 추적하고 싶은 사람
> - `t_key_binds` 테이블 기반 디스패치가 실제로 어떻게 구성되는지 보고 싶은 사람

## 1. 훅 등록

`render_create()` 내부에서 MLX 훅을 등록합니다.

- `mlx_hook(win, 17, 0, close_window, render)` — 윈도우 닫기
- `mlx_hook(win, 2,  ...,  handle_key, render)` — 키 프레스
- `mlx_expose_hook(win, handle_expose, render)` — 노출 이벤트
- `mlx_loop_hook(mlx, render_loop, render)` — 프레임 루프

세 핸들러는 `src/interact/event_dispatch.c` 에 정의되어 있고, `render_loop` 은 이전 문서에서 다뤘습니다.

## 2. handle_key — 테이블 탐색

`src/interact/event_dispatch.c:51`:

```c
int handle_key(int keycode, void *param)
{
    t_render *render = (t_render *)param;
    if (keycode == KEY_ESC)
        close_window(param);
    i = 0;
    while (i < render->key_binds.count)
    {
        if (render->key_binds.entries[i].keycode == keycode)
            return (render->key_binds.entries[i].handler(render, keycode), 0);
        i++;
    }
    return (0);
}
```

ESC 는 하드 코딩, 나머지는 **바인딩 테이블 선형 탐색**.

## 3. 바인딩 테이블

`includes/interact/key_binds.h` 에 정의된 구조:

```c
typedef void (*t_key_handler)(t_render *render, int keycode);

typedef struct s_key_bind {
    int              keycode;
    t_key_handler    handler;
} t_key_bind;

typedef struct s_key_binds {
    t_key_bind entries[KEY_BIND_COUNT];
    int        count;
} t_key_binds;
```

`bind_key()` 가 한 엔트리씩 추가하며, 초기화는 `src/interact/input/input_key_binds.c` / `input_key_binds_extra.c` 에 그룹별로 나뉘어 있습니다.

- `init_hud_binds` — H / TAB / UP / DOWN / = 키
- `init_camera_binds` — W/X/A/D/Q/Z/E/C/S/1/3
- `init_transform_move_binds` — R/T/F/G/V/B/[/]/;/'/,/.
- `init_transform_resize_binds`, `init_transform_rotate_binds` — Y/U/N/M/I/J/O/K/P/L

모든 키가 동일한 서너 개의 그룹 핸들러(`handle_camera_keys`, `handle_transform_keys`, `handle_hud_keys`) 중 하나로 라우팅됩니다.

## 4. 그룹 핸들러 — handle_camera_keys

`src/interact/input/input_dispatch.c:27`:

```c
void handle_camera_keys(t_render *render, int keycode)
{
    if (keycode ∈ {W,X,A,D,Q,Z}) {
        handle_camera_move(render, keycode);
        debounce_on_input(&render->debounce, render);
        hud_mark_dirty(render);
    } else if (keycode ∈ {E, C}) {
        handle_camera_pitch(render, keycode);
        ...
    } else if (keycode == S) {
        handle_camera_reset(render);
        ...
    } else if (keycode ∈ {1, 3}) {
        handle_camera_yaw(render, keycode);
        ...
    }
}
```

이 구조는 세 번 반복되는 세트 공통 후행 단계를 드러냅니다.

1. 실제 상태 변경 (`handle_camera_move` 등)
2. `debounce_on_input` 호출 → 미리보기 FSM 기동
3. `hud_mark_dirty` 호출 → HUD 다시 그릴 것을 표시

## 5. 카메라/객체/광원 핸들러 상세

- `handle_camera_move` (`input_camera.c`): 키에 따라 `camera.position` 을 basis 벡터에 따라 더함. 캐시 `valid=0`.
- `handle_camera_pitch`: `camera.pitch` ± 단계 증분. 범위 제한 후 `direction` 재계산.
- `handle_camera_reset`: `position`, `direction` 을 `initial_*` 로 복원.
- `handle_object_move/resize/rotate` (`input_objects.c`, `input_resize.c`, `input_rotate.c`): 선택된 객체의 타입별 데이터를 수정. 움직이면 바운드가 변하므로 `RENDER_BVH_DIRTY` 플래그를 세팅.
- `handle_light_move`: 선택된 광원 위치를 이동.

HUD 관련:

- `handle_hud_keys` (`input_dispatch.c:119`): H 토글, TAB 선택 순환, UP/DOWN 페이지, `=` 광원 선택 순환.

## 6. 디바운스 연결

모든 핸들러가 마지막에 `debounce_on_input()` 을 부르면:

1. FSM 이 IDLE → ACTIVE 로 이동
2. `RENDER_LOW_QUALITY | RENDER_DIRTY` 설정
3. 타이머 start

다음 `render_loop` 에서 low-quality 프레임이 즉시 렌더되어 시각적 피드백이 바로 나옵니다. 키 입력이 멎으면 150ms 후 FINAL 로 이동해 풀 퀄리티 렌더 (`심화-렌더링-파이프라인.md` 참조).

## 7. expose 이벤트

창이 다른 창에 가려졌다가 다시 보이면 X11/AppKit 가 expose 이벤트를 보냅니다. `handle_expose()` (`event_dispatch.c:78`) 는 마지막 프레임 버퍼를 그대로 다시 put 하여 빈 화면을 방지.

## 8. 종료

close 버튼 또는 ESC 키 → `close_window()` → bump map 해제 + render_destroy + scene_destroy + `exit(0)`. MLX는 exit 기반 종료가 관용적입니다.
