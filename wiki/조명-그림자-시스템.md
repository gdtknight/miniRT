# 조명/그림자 시스템

miniRT의 조명 시스템은 Phong 반사 모델을 기반으로 하며, 소프트 섀도우, 체커보드 텍스처, 범프 맵을 지원합니다.

---

## 소스 파일

### Shading (`src/lighting/shading/`)

| 파일 | 역할 |
|------|------|
| `shading.c` | `apply_lighting` -- 다중 광원 Phong 모델 적용 + 체커보드/범프맵 hook |
| `shading_utils.c` | `clamp_color`, `fast_pow32` -- 조명 유틸리티 |

### Shadow (`src/lighting/shadow/`)

| 파일 | 역할 |
|------|------|
| `shadow_calc.c` | `calculate_shadow_factor` -- 소프트 섀도우 팩터 계산 |
| `shadow_occlusion.c` | `is_in_shadow` -- 단일 shadow ray 차폐 테스트 |
| `shadow_config.c` | `init_shadow_config` -- 그림자 설정 초기화 + offset LUT |

## Phong 조명 모델

Phong 모델은 Ambient(주변광) + Diffuse(난반사) + Specular(정반사) 세 요소로 구성됩니다.

```
최종 색상 = object_color * (Ambient + Diffuse + Specular)
```

### 공식

| 요소 | 공식 | 설명 |
|------|------|------|
| Ambient | `K_a * I_a * object_color` | 간접 조명. 모든 점에서 동일 |
| Diffuse | `I_d * max(0, N . L) * object_color` | Lambert 코사인 법칙. 광원을 향할수록 밝음 |
| Specular | `0.5 * I_s * (R . V)^32 * light_color` | 광택 하이라이트. 반사 벡터와 시선 벡터의 관계 |

- `N`: 표면 법선, `L`: 광원 방향, `R`: 반사 벡터 (`2(N . L)N - L`), `V`: 시선 벡터

### apply_lighting 실행 흐름

```
apply_lighting(scene, hit)
 1. 체커보드 hook: has_checker -> checkerboard_color()로 hit->color 교체
 2. 범프맵 hook: bump_map -> bump_perturb_normal()로 hit->normal 교란
 3. view_dir = normalize(camera.position - hit.point)
 4. for each light in lights[0..light_count-1]:
    a. light_dir = normalize(light.position - hit.point)
    b. diffuse = max(0, dot(normal, light_dir))
    c. shadow_factor = calculate_shadow_factor(...)
       (내부에서 ceil(samples / light_count)로 광원 수 비례 조절)
    d. specular = fast_pow32(max(0, dot(reflect_dir, view_dir))) * 0.5
    e. acc += (diffuse + specular) * (1 - shadow_factor) * brightness * light_color
 5. final_color = clamp(object.color * (ambient + acc), 0, 255)
```

## Specular 최적화

`pow(x, 32.0)` 대신 `fast_pow32(x)` 사용:

```
x^2 -> x^4 -> x^8 -> x^16 -> x^32  (곱셈 5회, pow() 호출 제거)
```

5번의 곱셈만으로 x^32를 계산하여 `<math.h>`의 `pow()` 호출을 완전히 제거합니다. Specular 계산은 모든 픽셀의 모든 광원에서 실행되므로, 이 최적화의 누적 효과는 상당합니다.

## 소프트 섀도우

### 알고리즘

실제 세계의 광원은 점이 아니라 면적을 가지므로, 부드러운 그림자 경계(penumbra)가 생깁니다. 광원 주변의 여러 지점에서 shadow ray를 발사하여 차폐 비율을 계산합니다.

1. Hit point에서 광원 방향으로 여러 shadow ray 발사
2. 각 ray에 offset을 적용하여 광원 주변을 샘플링
3. 차폐된 ray 비율 = shadow factor (0.0: 완전 조명, 1.0: 완전 그림자)

```
calculate_shadow_factor(scene, query, light_pos, config)
 |-- calculate_shadow_bias(normal, light_dir, base_bias)
 +-- for i in [0, samples):
      |-- offset_lut != NULL -> offset = offset_lut[i] * radius
      |    +-- offset_lut == NULL -> generate_shadow_sample_offset() 폴백
      |-- sample_pos = light_pos + offset
      +-- is_in_shadow(scene, biased_point, sample_pos, bias)
           |-- BVH any-hit (objects > threshold)
           |    +-- bvh_any_hit()
           +-- brute-force (objects <= threshold)
                +-- 모든 오브젝트 순회
```

### Shadow Offset LUT

`init_shadow_offset_lut()`에서 grid-based stratified 오프셋을 1회 사전 계산합니다:

```c
grid_size = (int)sqrt(samples);
for (i = 0; i < samples; i++)
{
    angle = 2 * PI * (i % grid_size) / grid_size;
    r = (i / grid_size + 0.5) / grid_size;
    lut[i] = (t_vec3){r * cos(angle), r * sin(angle), 0};
}
```

- Grid 기반 층화 샘플링으로 균일한 분포 보장
- 매 shadow sample에서 삼각함수(`cos`, `sin`, `sqrt`) 호출 제거
- `scene_destroy()` 시 LUT 메모리 해제

### Adaptive Shadow Bias

표면 각도에 따라 bias를 조절하여 shadow acne(자기 교차 아티팩트)를 방지합니다:

```c
double calculate_shadow_bias(t_vec3 normal, t_vec3 light_dir, double base_bias)
```

- `angle_factor = 1.0 - |dot(normal, light_dir)|`
- `bias = base_bias * (1.0 + angle_factor * 2.0)`
- `base_bias = 0.001` 고정
- 법선과 광원 방향의 각도가 클수록(grazing angle) bias가 증가하여 아티팩트 방지

## Shadow BVH 분기

`is_in_shadow()`에서 BVH 활성화 여부와 오브젝트 수에 따라 분기합니다:

```
is_in_shadow(scene, point, light_pos, bias)
 |-- BVH 활성화 && objects > SHADOW_BVH_THRESHOLD (5)
 |    |-- bvh_any_hit() -> hit -> return 1 (early exit)
 |    +-- check_plane_shadow() -> plane 별도 순회
 +-- 그 외
      +-- check_object_shadow() -> brute-force 전체 순회
```

| 조건 | 경로 |
|------|------|
| BVH 활성화 + objects > 5 | `bvh_any_hit()` + `check_plane_shadow()` |
| 그 외 | `check_object_shadow()` brute-force 순회 |

- Any-hit는 첫 번째 차폐 발견 시 즉시 종료하므로 일반 BVH 순회보다 빠름
- BVH 경로에서는 plane이 BVH에 포함되지 않으므로 `check_plane_shadow()`로 별도 테스트

## 텍스처

### 체커보드 패턴

오브젝트에 `checker` 옵션이 설정된 경우, UV 좌표 기반으로 체커보드 패턴을 적용합니다.

- 교차점의 UV 좌표를 계산하여 격자 위치를 결정
- 격자 위치에 따라 원래 색상과 반전 색상을 교대로 적용 (color swap)
- `apply_lighting` 흐름의 첫 번째 단계에서 `hit->color`를 교체

### 범프 맵

오브젝트에 `bump <file.xpm>` 옵션이 설정된 경우, XPM 이미지를 기반으로 법선을 섭동합니다.

- `bump_map_load.c`: XPM 파일을 MiniLibX의 `mlx_xpm_file_to_image()`로 로딩
- `bump_map_perturb.c`: 범프맵의 높이값 차이를 이용하여 표면 법선을 미세하게 교란
- 법선 섭동(normal perturbation)으로 평면 표면에 요철 효과를 부여
- `apply_lighting` 흐름에서 체커보드 다음, 조명 계산 전에 적용
