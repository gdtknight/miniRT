# 심화: 파서 흐름

> 이 문서는 누구를 위한 것인가
> - `.rt` 파일이 `t_scene` 구조체로 채워지는 호출 체인을 전체적으로 파악하고 싶은 사람
> - 보너스 옵션(checker, bump)이 어디서 붙는지 확인하고 싶은 사람
> - 파서가 보장하는 "invariant" 의 근거를 직접 눈으로 확인하고 싶은 사람

## 1. 한눈에 보는 호출 체인

```
main() [src/main.c:132]
  └── init_scene(filename, &scene)
        ├── scene_create()              // t_scene 할당 + 기본값
        └── parse_scene(filename, scene)  [src/scene/parser/parser.c:132]
              ├── validate_extension()
              ├── open(filename, O_RDONLY)
              ├── line_reader_init()
              └── process_lines(reader, scene, ctx)
                    └── (반복) parse_line(line, scene, ctx)
                          └── dispatch_line()   [parser_dispatch.c:108]
                                ├── dispatch_scene_element()  ← A, C, L
                                │     ├── parse_ambient()
                                │     ├── parse_camera()
                                │     └── parse_light()
                                └── dispatch_object()         ← sp, pl, cy, co
                                      ├── parse_sphere()
                                      ├── parse_plane()
                                      ├── parse_cylinder()
                                      └── parse_cone()
              └── validate_scene()      // invariant 강제
```

## 2. 라인 리더 — 줄 단위로 읽기

`src/scene/parser/parse_line_reader.c` 가 파일 디스크립터에서 한 줄씩 읽어 문자열을 리턴합니다. 실패 원인은 `reader->error` 에 기록되며, 한 줄이 너무 길면 `line_too_long` 플래그가 세워집니다 (`parser.c:73`).

한 줄을 얻으면 `parse_line()` → `dispatch_line()` 을 거쳐 적절한 파서로 라우팅합니다.

## 3. 디스패치 — 첫 토큰으로 분기

`src/scene/parser/parser_dispatch.c:108` 의 `dispatch_line()` 은:

1. 앞쪽 공백을 건너뜀 (`skip_whitespace`).
2. 빈 줄이거나 `#` 으로 시작하면 주석으로 간주하고 `PARSE_OK` 반환.
3. `dispatch_scene_element()` 로 A/C/L 을 우선 검사.
4. 그 다음 `dispatch_object()` 로 sp/pl/cy/co 검사.
5. 둘 다 실패하면 `PARSE_ERR_UNKNOWN_ELEMENT`.

식별자는 `matches_prefix()` 로 엄격히 비교하며, 뒤에 공백/탭이 와야만 매치됩니다(예: `spam` 은 `sp` 로 잘못 매칭되지 않음, `parser_dispatch.c:34`).

## 4. 요소 파서 — 공통 패턴

모든 요소 파서는 같은 스타일을 따릅니다.

```
1. 중복 검사 (A, C 는 1개만 허용)
2. 스킵 공백
3. parse_vector_strict, parse_double, parse_color_strict 호출
4. 범위 검증 (validate_coordinate_range, in_range 등)
5. 필요시 정규화 (vec3_normalize)
6. 라인 끝 검증 (at_line_end)
7. scene 에 기록 + 플래그 세트
```

### 예: parse_ambient

`src/scene/parser/parse_elements.c:25`:

```c
if ((scene->flags & SCENE_HAS_AMBIENT))
    return (PARSE_ERR_DUPLICATE);
token = skip_whitespace(line + 2);
result = parse_double(token, &ratio, &token);
if (result != PARSE_OK) return (result);
if (!in_range(ratio, 0.0, 1.0)) return (PARSE_ERR_RANGE);
scene->ambient.ratio = ratio;
...
scene->flags |= SCENE_HAS_AMBIENT;
```

파서가 색상/비율을 한번 유효 범위로 밀어 넣었기 때문에, 렌더러는 이후 클램프를 다시 하지 않아도 됩니다.

### 예: parse_camera

`parse_elements.c:111` 에서 position, direction, fov 를 읽고 `init_camera_state()` 가 `initial_position`, `initial_direction`, `pitch`, `yaw` 를 세팅합니다. 이는 S 키 리셋과 E/C 키 피치 회전에 쓰입니다.

## 5. 객체 파서와 보너스 옵션

`src/scene/parser/parse_objects.c` 와 `parse_cylinder.c`, `parse_cone.c` 가 각 도형을 처리합니다. 공통 뼈대는:

```c
ft_bzero(&obj, sizeof(t_object));
obj.type = OBJ_<TYPE>;
token = skip_whitespace(line + N);

// 1. 위치/축/반지름/높이 등 타입별 데이터
parse_vector_strict(...);
...

// 2. 색상
parse_color_strict(...);

// 3. 보너스 옵션(checker, bump)
parse_bonus_options(&token, &obj);

// 4. ID 부여 + 씬에 추가
format_id(obj.id, 16, "sp-", get_type_count(scene, OBJ_SPHERE) + 1);
object_list_add(&scene->objects, &obj);
```

### 보너스 옵션 처리

`src/scene/parser/parse_bonus_options.c:95` 의 `parse_bonus_options()` 는 줄 끝까지 남은 토큰을 훑으며:

- `checker:<R,G,B>` → `obj->has_checker = 1`, `obj->checker_color` 설정
- `bump:<path>` → `obj->bump_path` 문자열 복제(실제 로딩은 main 에서 MLX 준비 후)

잘못된 토큰이 남아 있으면 `PARSE_ERR_TRAILING_TOKEN`.

## 6. 검증 — invariant 확정

모든 줄을 처리한 뒤 `validate_scene()` 이 호출됩니다 (`parser.c:53`):

```c
if (!(scene->flags & SCENE_HAS_AMBIENT)) return (error..., 0);
if (!(scene->flags & SCENE_HAS_CAMERA))  return (error..., 0);
if (scene->light_count == 0)             return (error..., 0);
if (scene->objects.count == 0)           return (error..., 0);
```

이 네 가지가 통과하면 CLAUDE.md 에 나열된 Parser Invariant 가 완성됩니다.

- ambient × 1, camera × 1, light ≥ 1, objects ≥ 1
- 색상 [0,255], 비율 [0,1], 축 벡터 정규화 + 0 아님
- FOV ∈ [1, 179]
- 실린더/원뿔의 반지름·높이 > 0

렌더 파이프라인은 이 invariant를 믿고 중복 검사를 하지 않습니다.

## 7. 에러 리포팅

`t_error_context` (`common/error.h`) 가 현재 줄 번호, 요소 타입("Sphere", "Camera"...) 을 들고 다니며, 실패 시 `error_context_print()` 가 "Line 12 Sphere: invalid color" 같은 메시지를 stderr 에 찍습니다.
