# 아키텍처

miniRT의 전체 아키텍처, 렌더링 파이프라인, 핵심 자료구조를 설명합니다.

---

## 전체 실행 흐름

```
main()
 ├── parse_args()           # 인자 파싱 (파일명, --bvh-vis)
 ├── init_and_parse()        # scene_create + parse_scene + scene_build_bvh
 ├── init_render_ctx()       # render_create + load_all_bump_maps
 └── mlx_loop()              # 이벤트 루프 진입
      └── render_loop()      # 매 프레임 콜백
           ├── debounce_update()          # 디바운스 FSM 상태 전이
           ├── rebuild_bvh_if_dirty()     # BVH 재구축 (필요 시)
           ├── [RENDER_DIRTY] execute_render_pass()
           │    ├── metrics_start_frame()
           │    ├── render_scene_to_buffer()
           │    │    ├── create_camera_ray()
           │    │    ├── trace_ray()
           │    │    └── put_pixel_to_buffer()
           │    ├── metrics_end_frame()
           │    └── mlx_put_image_to_window()
           ├── hud_render()
           └── keyguide_render()
```

1. `.rt` 파일을 파싱하여 씬 데이터를 구성한다.
2. Bounded 오브젝트(구, 원기둥, 원뿔)로 BVH 트리를 구축한다. Plane은 무한 AABB 문제로 별도 관리한다.
3. MiniLibX 이벤트 루프에 진입하여 매 프레임마다 `render_loop()`을 콜백한다.
4. 디바운스 FSM이 입력 상태를 관리하고, `RENDER_DIRTY` 플래그가 설정된 경우에만 렌더링을 수행한다.

## 모듈 의존성

```
           ┌──────────┐
           │  main.c  │
           └────┬─────┘
      ┌─────────┼─────────┐
      v         v         v
 ┌────────┐ ┌───────┐ ┌────────┐
 │ parser │ │ scene │ │display │
 └───┬────┘ └───┬───┘ └───┬────┘
     │          │         │
     v          v         v
 ┌────────────────────────────┐
 │         render             │
 │  (camera, trace, metrics)  │
 └──────┬──────────┬──────────┘
        │          │
   ┌────v───┐  ┌────v────┐
   │ spatial │  │ shading │
   │  (BVH)  │  │(shadow) │
   └────┬────┘  └────┬────┘
        │            │
        v            v
   ┌─────────┐  ┌────────┐
   │intersect│  │  math  │
   │         │  │(vector)│
   └─────────┘  └────────┘
```

- `parser`: `.rt` 파일을 파싱하여 `t_scene`을 구성
- `scene`: 씬 생명주기 관리 (생성, 파괴, BVH 구축)
- `display`: MiniLibX 초기화, 이벤트 바인딩, 픽셀 출력
- `render`: 카메라 레이 생성, 레이 트레이싱 디스패치, 디바운스, 성능 메트릭
- `spatial`: BVH 구축/순회, AABB 연산
- `shading`: Phong 조명 모델 (다중 광원, fast_pow32)
- `shadow`: 소프트 섀도우, offset LUT, BVH any-hit
- `intersect`: 광선-오브젝트 교차 판정 (구, 평면, 원기둥, 원뿔)
- `math`: 벡터 연산 (add, sub, dot, cross, normalize)

## 렌더링 파이프라인

### 카메라 레이 생성

`create_camera_ray()`가 각 픽셀에 대해 카메라 위치에서 뷰포트를 통과하는 레이를 생성한다. 카메라 basis 벡터(right, up)는 `t_camera_cache`에 캐싱하여 프레임당 1회만 계산한다.

카메라 방향벡터로부터 직교 정규 기저를 생성한다:

```
forward = normalize(camera.direction)
right   = normalize(cross(forward, world_up))
up      = cross(right, forward)
```

각 픽셀 (x, y)에 대해 NDC 좌표를 계산하고, FOV 스케일과 종횡비를 적용하여 광선 방향을 결정한다.

### 레이 트레이싱

```
trace_ray(scene, ray)
 ├── BVH 활성화 → bvh_intersect() + plane 별도 테스트
 │    └── bvh_node_intersect() → aabb_intersect() → intersect_object_new()
 └── BVH 비활성화 → brute-force (모든 오브젝트 순회)
 └── hit 발생 → apply_lighting()
```

- BVH 트리를 ordered traversal (가까운 자식 먼저)로 순회
- Plane은 BVH에서 분리되어 별도 선형 테스트
- `t_max` pruning으로 불필요한 노드 탐색 제거

### 조명 계산

각 hit point에 대해 Phong 모델을 적용한다:

1. 체커보드 색상 교체 (활성화 시)
2. 범프맵 법선 교란 (활성화 시)
3. 다중 광원 루프: 각 광원별 독립 계산
   - Shadow factor: 소프트 섀도우 (동적 샘플 조절)
   - Diffuse: Lambert 반사 (`dot(N, L)`)
   - Specular: Phong 반사 (`pow(dot(R, V), 32) * 0.5`)
4. Ambient: 균일 환경광 + 광원 기여 합산
5. 최종 RGB 클램핑 [0, 255]

### 품질 모드와 디바운스

- **Full quality**: 모든 픽셀 개별 렌더링
- **Low quality**: 인터랙션 중 블록 단위 렌더링 (빠른 프리뷰)

입력 이벤트 발생 시 디바운스 FSM이 LQ preview를 50ms 간격으로 트리거하고, 150ms 입력 없으면 full quality 렌더링을 수행한다.

상태 머신: `IDLE -> ACTIVE (150ms) -> FINAL (FQ render) -> COOLDOWN (350ms) -> IDLE`

## 핵심 자료구조

### t_scene

전체 씬 상태를 담는 최상위 구조체.

```c
typedef struct s_scene
{
    t_ambient       ambient;              // 환경광
    t_camera        camera;               // 카메라
    t_light         lights[MAX_LIGHTS];   // 광원 배열 (최대 16)
    int             light_count;          // 현재 광원 수
    int             selected_light;       // 조작 대상 광원 인덱스
    t_shadow_config shadow_config;        // 그림자 설정
    t_object_list   objects;              // 오브젝트 동적 배열
    int             flags;                // 씬 상태 비트 플래그
    t_bvh           *bvh;                 // BVH 트리 포인터
    t_metrics       metrics;              // 성능 메트릭
}   t_scene;
```

플래그: `SCENE_HAS_AMBIENT (0x01)`, `SCENE_HAS_CAMERA (0x02)`, `SCENE_BVH_ENABLED (0x08)`

### t_object

통합 오브젝트 구조체. union으로 타입별 데이터를 공유한다.

```c
typedef struct s_object
{
    t_object_type   type;           // OBJ_SPHERE, OBJ_PLANE, OBJ_CYLINDER, OBJ_CONE
    t_color         color;          // RGB 색상
    t_color         checker_color;  // 체커보드 보조 색상
    int             has_checker;    // 체커보드 활성화 여부
    char            *bump_path;     // 범프맵 XPM 파일 경로
    t_bump_map      *bump_map;      // 범프맵 데이터 (지연 로드)
    char            id[16];         // 식별자 (예: "sp-1", "cy-2")
    union u_object_data
    {
        t_sphere_data   sphere;     // center, radius, radius_sq
        t_plane_data    plane;      // point, normal
        t_cylinder_data cylinder;   // center, axis, radius, radius_sq, half_height
        t_cone_data     cone;       // center, axis, radius, radius_sq, half_height
    }   data;
}   t_object;
```

타입 열거형:

```c
typedef enum e_object_type
{
    OBJ_NONE = 0,
    OBJ_SPHERE,
    OBJ_PLANE,
    OBJ_CYLINDER,
    OBJ_CONE
}   t_object_type;
```

### t_ray / t_hit

```c
typedef struct s_ray
{
    t_vec3  origin;     // 광선 시작점
    t_vec3  direction;  // 방향 (정규화)
    t_vec3  inv_dir;    // 1/direction (AABB 교차용, 사전 계산)
}   t_ray;

typedef struct s_hit
{
    double      distance;  // 교차 거리 (t값)
    t_vec3      point;     // 교차점 좌표
    t_vec3      normal;    // 교차점 법선
    t_color     color;     // 오브젝트 색상
    t_object    *obj;      // 교차된 오브젝트 포인터
}   t_hit;
```

- `inv_dir`은 광선 생성 시 사전 계산되어 AABB slab method에서 나눗셈을 곱셈으로 대체한다.
- `t_hit.obj`는 체커보드/범프맵 접근에 사용된다.

### t_bvh / t_bvh_node / t_aabb

```c
typedef struct s_bvh
{
    t_bvh_node      *root;         // 트리 루트
    int             enabled;       // 활성화 여부
    int             visualize;     // 시각화 플래그
    t_plane_refs    plane_refs;    // 분리된 plane 인덱스
}   t_bvh;

typedef struct s_bvh_node
{
    t_aabb              bounds;        // 바운딩 박스
    struct s_bvh_node   *left;         // 좌측 자식
    struct s_bvh_node   *right;        // 우측 자식
    t_object_ref        *objects;      // 리프 오브젝트 목록
    int                 object_count;  // 리프 오브젝트 수
    int                 depth;         // 노드 깊이
    int                 split_axis;    // 분할 축 (0=x, 1=y, 2=z)
}   t_bvh_node;

typedef struct s_aabb
{
    t_vec3  min;  // 각 축 최솟값
    t_vec3  max;  // 각 축 최댓값
}   t_aabb;
```

- Plane은 `t_plane_refs`에 별도 저장되며 BVH 트리에 포함되지 않는다.
- 리프 노드는 `objects` 배열에 오브젝트 참조를 보유하고, 내부 노드는 `left`/`right` 자식을 가진다.

### t_render

렌더 컨텍스트. MiniLibX 핸들과 씬, UI 상태를 통합 관리한다.

```c
typedef struct s_render
{
    t_mlx_context       mlx;            // MiniLibX 핸들
    t_scene             *scene;         // 씬 포인터
    t_selection         selection;      // 선택된 오브젝트
    int                 state_flags;    // 렌더 상태 비트 플래그
    t_hud_state         hud;            // HUD 상태
    t_keyguide_state    keyguide;       // 키가이드 상태
    t_pixel_timing      pixel_timing;   // 픽셀 타이밍
    t_debounce_state    debounce;       // 디바운스 상태
}   t_render;
```

렌더 상태 플래그:

| 플래그 | 값 | 설명 |
|--------|------|------|
| `RENDER_DIRTY` | 0x01 | 재렌더링 필요 |
| `RENDER_RENDERING` | 0x02 | 렌더링 진행 중 |
| `RENDER_LOW_QUALITY` | 0x04 | 저품질 프리뷰 모드 |
| `RENDER_BVH_DIRTY` | 0x20 | BVH 재구축 필요 |
| `RENDER_ENABLE_PIXEL_TIMING` | 0x40 | 픽셀 타이밍 측정 활성화 |
| `RENDER_ENABLE_METRICS_PRINT` | 0x80 | 콘솔 메트릭 출력 활성화 |

### t_debounce_state

디바운스 FSM 상태 관리.

```c
typedef enum e_debounce_state_enum
{
    DEBOUNCE_IDLE,       // 대기 상태
    DEBOUNCE_ACTIVE,     // 입력 감지 (150ms 대기)
    DEBOUNCE_FINAL,      // Full quality 렌더링
    DEBOUNCE_COOLDOWN    // 쿨다운 (350ms)
}   t_debounce_state_enum;

typedef struct s_debounce_state
{
    t_debounce_state_enum  state;             // FSM 현재 상태
    t_debounce_timer       timer;             // 입력 지연 타이머
    struct timeval         last_preview_time;  // 마지막 LQ 프리뷰 시각
}   t_debounce_state;
```

## 플랫폼 지원

macOS (OpenGL + AppKit)와 Linux (X11 + Xext) 두 플랫폼을 지원한다.

- **키 코드**: `includes/input.h`에서 `#ifdef __APPLE__` / `__linux__`로 이중 정의
- **MLX 정리**: Linux에서는 `mlx_destroy_display()` 호출 필요 (macOS에서는 미제공)
- **빌드**: Makefile이 `uname -s`로 OS를 자동 감지하여 링크 플래그 설정
