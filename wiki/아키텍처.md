# 아키텍처

miniRT의 전체 아키텍처, 렌더링 파이프라인, 핵심 자료구조를 설명합니다.

---

## 전체 실행 흐름

```
main()
 ├── parse_args()            # 인자 파싱 (파일명, --bvh-vis)
 ├── init_scene()             # scene_create + parse_scene
 ├── build_scene_bvh()        # BVH 트리 구축 (plane 분리)
 ├── bvhd_run()               # --bvh-vis 플래그 시 콘솔 출력
 ├── init_render()            # render_create (MLX 초기화, HUD/Keyguide 초기화)
 ├── load_textures()          # load_all_bump_maps
 └── mlx_loop()               # 이벤트 루프 진입
      └── render_loop()       # 매 프레임 콜백
           ├── debounce_update()          # 디바운스 FSM 상태 전이
           ├── rebuild_bvh_if_dirty()     # BVH 재구축 (필요 시)
           ├── [RENDER_DIRTY] execute_render_pass()
           │    ├── metrics_start_frame()
           │    ├── render_scene_to_buffer()
           │    │    ├── create_camera_ray()
           │    │    ├── trace_ray()
           │    │    └── put_pixel_to_buffer()
           │    ├── metrics_end_frame()
           │    └── mlx_put_image_to_window()
           ├── hud_render()
           └── keyguide_render()
```

1. `.rt` 파일을 파싱하여 씬 데이터를 구성한다.
2. Bounded 오브젝트(구, 원기둥, 원뿔)로 BVH 트리를 구축한다. Plane은 무한 AABB 문제로 별도 관리한다.
3. MiniLibX 이벤트 루프에 진입하여 매 프레임마다 `render_loop()`를 콜백한다.
4. 디바운스 FSM이 입력 상태를 관리하고, `RENDER_DIRTY` 플래그가 설정된 경우에만 렌더링을 수행한다.

## 모듈 구성 (7 패키지)

리팩토링 이후 소스는 기능 기반(feature-based) 7개 패키지로 구성된다. 모든 공개 헤더는 `includes/` 이하에 `src/`와 동일한 구조로 배치되며, `#include "package/header.h"` 형식을 사용한다.

| 패키지 | 디렉토리 | 역할 |
|--------|---------|------|
| **common** | `src/common/` | Vec3 수학, 에러 처리, 포맷 헬퍼, 타이머 |
| **scene** | `src/scene/` | 씬 생명주기, 오브젝트 동적 배열, 비트 플래그 |
| | `src/scene/parser/` | `.rt` 파일 strict 파싱, 보너스 옵션 |
| **spatial** | `src/spatial/intersect/` | 광선-오브젝트 교차 (sphere, plane, cylinder, cone) |
| | `src/spatial/aabb/` | AABB 생성, 병합, 교차 |
| | `src/spatial/bvh/` | BVH 구축(midpoint split, 깊이 20), 순회, any-hit |
| | `src/spatial/debug/` | `--bvh-vis` 콘솔 트리 덤프 (`bvhd_*`) |
| **render** | `src/render/` | 렌더 루프, 카메라 레이, trace 분기, 디바운스, MLX 창/픽셀 |
| **lighting** | `src/lighting/shading/` | Phong 모델, 다중 광원, `fast_pow32()` |
| | `src/lighting/shadow/` | 소프트 섀도우(stratified), offset LUT, 차폐 테스트 |
| | `src/lighting/texture/` | 체커보드, XPM 범프맵 로딩/법선 섭동 |
| **interact** | `src/interact/` | 이벤트 디스패치 (창 닫기, 키, 노출) |
| | `src/interact/input/` | 카메라/오브젝트/광원 조작 키 핸들러 |
| | `src/interact/hud/` | HUD 오버레이, 페이지네이션 |
| | `src/interact/keyguide/` | 화면 키가이드 |
| **metrics** | `src/metrics/` | 프레임 시간, 레이/BVH 카운터 |

`metrics.h`는 모든 패키지가 참조하는 횡단 관심사(cross-cutting concern)로 `includes/` 최상위에 위치한다.

### 헤더 스코핑 규칙

- **공개 API 헤더** (예: `render/render.h`, `scene/scene.h`): 타 패키지에서 호출 가능한 타입/함수.
- **내부 헤더** (`_internal.h` 접미사, 예: `spatial/bvh_internal.h`, `spatial/bvhd_internal.h`): 해당 서브패키지 내부 구현에서만 사용. 외부 include 금지.
- **타입 전용 헤더** (예: `interact/ui_types.h`, `interact/key_binds.h`, `render/window.h`): 여러 패키지가 구조체 멤버로 임베드하는 공유 타입 — 순환 의존을 끊기 위함.

모든 `.c`는 자신이 참조하는 심볼을 정의하는 헤더를 직접 `#include`해야 하며, 간접(transitive) include에 의존하지 않는다.

## 렌더링 파이프라인

### 카메라 레이 생성

`create_camera_ray()`가 각 픽셀에 대해 카메라 위치에서 뷰포트를 통과하는 레이를 생성한다. 카메라 basis 벡터(right, up)는 `t_camera_cache`에 캐싱하여 프레임당 1회만 계산한다.

```
forward = normalize(camera.direction)
right   = normalize(cross(forward, world_up))
up      = cross(right, forward)
```

각 픽셀 (x, y)에 대해 NDC 좌표를 계산하고, FOV 스케일과 종횡비를 적용하여 광선 방향을 결정한다. `inv_dir` (1/direction)은 레이 생성 시 사전 계산되어 AABB slab method 교차에서 사용된다.

### 레이 트레이싱

```
trace_ray(scene, ray)
 ├── BVH 활성화 → bvh_intersect() + plane 별도 선형 테스트
 │    └── bvh_node_intersect() → aabb_intersect() → intersect_object()
 └── BVH 비활성화 → brute-force (모든 오브젝트 순회)
 └── hit 발생 → apply_lighting()
```

- Plane은 BVH에서 분리되어 `t_bvh.plane_refs`에 별도 저장된다.
- Ordered traversal(가까운 자식 우선) + `t_max` pruning.

### 조명 계산

각 hit point에 Phong 모델을 적용한다:

1. 체커보드 색상 교체 (활성화 시)
2. 범프맵 법선 교란 (활성화 시)
3. 다중 광원 루프:
   - Shadow factor: 소프트 섀도우 (stratified LUT, 광원 수에 비례 샘플 분배)
   - Diffuse: Lambert 반사 (`dot(N, L)`)
   - Specular: Phong 반사 (`fast_pow32(dot(R, V)) * 0.5`)
4. Ambient: 균일 환경광 + 광원 기여 합산
5. 최종 RGB 클램핑 [0, 255]

### 품질 모드와 디바운스

- **Full quality**: 모든 픽셀 개별 렌더링
- **Low quality**: 인터랙션 중 2x2 블록 단위 렌더링 (빠른 프리뷰)

상태 머신: `IDLE → ACTIVE (150ms) → FINAL (FQ 렌더) → COOLDOWN (350ms) → IDLE`. LQ 프리뷰는 50ms 스로틀로 연속 입력 중에도 과도한 렌더를 방지한다.

## 파서 불변식 (Parser Invariants)

`src/scene/parser/`는 렌더링 시작 전에 다음 불변식을 보장한다. 런타임 코드는 중복 검사 없이 이를 신뢰한다.

- ambient (`A`)와 camera (`C`)가 정확히 1개씩 존재
- `light_count >= 1`, `objects.count >= 1`
- 색상은 [0, 255], ratio/brightness는 [0.0, 1.0]로 클램핑
- 축 벡터는 정규화되며 영벡터가 아님
- 원기둥/원뿔의 지름·높이는 양수
- FOV ∈ [1, 179] (open interval로 `tan(fov/2)` 발산 방지)

## 핵심 자료구조

### t_scene

```c
typedef struct s_scene
{
    t_ambient       ambient;              // 환경광
    t_camera        camera;               // 카메라
    t_light         lights[MAX_LIGHTS];   // 광원 배열
    int             light_count;          // 현재 광원 수
    int             selected_light;       // 조작 대상 광원 인덱스
    t_shadow_config shadow_config;        // 그림자 설정 (scene 소유)
    t_object_list   objects;              // 오브젝트 동적 배열
    int             flags;                // 씬 상태 비트 플래그
    t_bvh           *bvh;                 // BVH 트리 포인터
    t_metrics       metrics;              // 성능 메트릭
}   t_scene;
```

`t_shadow_config`는 `t_scene`에 직접 임베드되며, 이로 인해 `scene.h`는 `lighting/`에 의존하지 않는다.

### t_object

```c
typedef struct s_object
{
    t_object_type   type;           // OBJ_SPHERE, OBJ_PLANE, OBJ_CYLINDER, OBJ_CONE
    t_color         color;
    t_color         checker_color;
    int             has_checker;
    char            *bump_path;
    t_bump_map      *bump_map;
    char            id[16];         // "sp-1", "cy-2" ...
    union u_object_data
    {
        t_sphere_data   sphere;
        t_plane_data    plane;
        t_cylinder_data cylinder;
        t_cone_data     cone;
    }   data;
}   t_object;
```

### t_ray / t_hit

```c
typedef struct s_ray
{
    t_vec3  origin;
    t_vec3  direction;  // 정규화
    t_vec3  inv_dir;    // 1/direction (AABB 교차 최적화)
}   t_ray;

typedef struct s_hit
{
    double      distance;
    t_vec3      point;
    t_vec3      normal;
    t_color     color;
    t_object    *obj;
}   t_hit;
```

통합 hit record로 `t_hit`만 사용한다 (`t_hit_record` alias 없음).

### t_bvh / t_bvh_node / t_aabb

```c
typedef struct s_bvh
{
    t_bvh_node      *root;
    int             enabled;
    int             visualize;    // --bvh-vis 플래그
    t_plane_refs    plane_refs;   // BVH에서 분리된 plane 인덱스
}   t_bvh;
```

- Plane은 `[-1e6, 1e6]^3`의 AABB로 BVH 품질을 저하시키므로 트리에 포함되지 않는다.
- BVH 함수는 `t_scene *` (void * 아님)로 씬을 받아 타입 안전성을 확보한다.

### t_render

```c
typedef struct s_render
{
    t_mlx_context       mlx;
    t_scene             *scene;
    t_selection         selection;
    int                 state_flags;
    t_hud_state         hud;
    t_keyguide_state    keyguide;
    t_pixel_timing      pixel_timing;
    t_debounce_state    debounce;
}   t_render;
```

주요 플래그: `RENDER_DIRTY`, `RENDER_RENDERING`, `RENDER_LOW_QUALITY`, `RENDER_BVH_DIRTY`, `RENDER_ENABLE_PIXEL_TIMING`, `RENDER_ENABLE_METRICS_PRINT`.

### t_debounce_state

```c
typedef enum e_debounce_state_enum
{
    DEBOUNCE_IDLE,
    DEBOUNCE_ACTIVE,
    DEBOUNCE_FINAL,
    DEBOUNCE_COOLDOWN
}   t_debounce_state_enum;
```

## 플랫폼 지원

macOS (OpenGL + AppKit)와 Linux (X11 + Xext) 양쪽 지원.

- **키 코드**: `includes/interact/input.h`에서 `#ifdef __APPLE__` / `__linux__`로 분기
- **MLX 정리**: Linux에서는 `mlx_destroy_display()` 추가 호출 (macOS 미제공)
- **빌드**: Makefile이 `uname -s`로 OS 자동 감지
